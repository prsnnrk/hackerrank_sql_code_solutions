README: The first thing I do is create a procedure called node_type to be able to identify the type of node, whether it is the 'Root', 'Leaf' or an 'Inner' node. Inside this procedure, I declare or create a cursor called c_node_pairs which basically selects all the node values and its corresponding parent values from the bst table, ordered by the node value. I then transfer this data into a table called t_nodes using FETCH ... BULK COLLECT INTO. I also store in node_row_count, the total number of records there are in the bst table. Then, I loop through the cursor of c_node_pairs and for each record/row of values, if its parent value is NULL, then the node is a 'Root' node. Else, if the parent value is NOT NULL, I check to see if the node value of this specific record has any match with any of the parent column values using a FOR LOOP with its cut-off range using the node_row_count derived earlier. If it does have a match, then the node itself can function as a parent node and is thus, not a 'Leaf', it is an 'Inner' node. Else, to check if a node is a 'Leaf' node, I calculate the number of times there is a 'no match' occurence between the node and the parent column values, and check to see if this count equals to the node_row_count or the number of total parent column values found in the bst table. It is worth noting that for the Root node, when the parent column value is NULL, then the equality or inequality comparison is not possible. Hence, a workaround to this would be to initialize the array to capture 'no match' values, with one 'no match' value upfront to cater for the Root node's P (parent) column value being NULL, which is present in the input. If the number of 'no match' occurrences tallies with the total number of P (parent) column values, as in, the node value is not found as part of the 'P' (parent) column values, then it is a 'Leaf' node because it is not a 'Parent' node and thus, there are no other nodes falling under it in the binary tree.
