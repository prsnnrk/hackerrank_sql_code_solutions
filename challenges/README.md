README: Firstly, I create a Common Table Expression (CTE) to contain the temporary result set of the hackers table joined with the challenges table where the hacker_id is the joining key and it matches from one table to the other, grouped by hacker_id and hacker_name and ordered by challenges in descending order, followed by hacker_id in ascending order. The columns queried here are hacker_id, name, and the count of challenge_id, indicating the number of challenges. Then, I create another CTE called row_num_challenges which contains the records extracted from the first CTE, called challenges_details, except that an addition of ROW_NUMBER() is included whereby it is PARTITIONED BY challenges and ORDERED BY hacker_id. This means that the records with the same number of challenges are given row_numbers sequentially, following the order of ascending hacker_id. I also construct another column which holds the count or number of records that have identical number of challenges for each grouping, and this column is referred to as total_count. After constructing all of the above CTEs, I then proceed to write a CASE statement which has 3 CASE options, being: 1. to fetch the details of the first record from every duplicate set of records which corresponds to the maximum number of challenges, 2. to fetch the details of the second record onwards from every duplicate set of records which correspond to the maximum number of challenges, 3. to fetch the details of the records which do not have any duplicates in terms of number of challenges. All of the records being passed through this CASE statement comes from a set of records which do not contain duplicate records in terms of number of challenges, where the number of challenges is not the maximum value of number of challenges. This result is then ordered by the number of challenges in descending order, followed by hacker_id in ascending order.
