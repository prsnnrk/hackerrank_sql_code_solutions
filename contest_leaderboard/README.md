README: The first thing I do is I create a Common Table Expression (CTE) to store the temporary result set of the hackers and submissions tables joined together with the hacker_id as the joining key, whereby it matches from one table to the other. The columns queried here are the hacker_id, name, challenge_id, submission_id and score for each submission. This is accompanied by two other add-on columns constructed which are row_num and number_of_submissions. The values of the row_num column is populated by using the ROW_NUMBER() function which populates the records with sequential row numbers based on the grouping or PARTITION of duplicate challenge_id and hacker_id, meaning the row numbers denote how many submissions a hacker has made for a particular challenge. This is then ORDERED BY ASCENDING submission_id for each grouping. The number_of_submissions column, on the other hand, is derived by using the COUNT(*) OVER function to count the records which are PARTITIONED or grouped by challenge_id and hacker_id, demanding both these column values to be duplicates across records in order to be counted as the number_of_submissions made by a hacker for the same challenge.
Next, from the hackers_submissions CTE, I create another CTE, called max_scores. Max_scores queries the hacker_id, name, challenge_id, and MAX(score) for each challenge by GROUPING these records BY hacker_id, name, and challenge_id, and then, ORDERING BY hacker_id. Finally, the total_scores CTE is closer to achieving the requirements of the question, which is to query the hacker_id, name, and the SUM of the max_score derived from the max_scores CTE earlier, GROUPED BY hacker_id and name. This basically means the max_scores will be summed up for each hacker. Lastly, I select all the data from total_scores but filter out the total_scores which yield in 0, and ORDER the result BY total_score in DESCENDING order, followed by hacker_id in ASCENDING order.
